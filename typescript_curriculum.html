1.1 What TypeScript is and is not

TypeScript · Compile-Time Safety vs Runtime Reality
// 1. TypeScript is an ERASE-ONLY type system
type User = { id: string; name: string; email: string };

// ⚠️ At runtime, fetch returns raw unknown JSON, NOT a verified User:
async function fetchUser(id: string): Promise<User> {
  const res = await fetch(`/api/users/${id}`);
  const data = await res.json(); 
  return data as User; // ❌ DANGEROUS: TypeScript checks this at compile-time only!
}

// ✅ PRODUCTION PATTERN: Validate with a runtime parser like Zod
import { z } from "zod";
const UserSchema = z.object({ id: z.string(), name: z.string(), email: z.string().email() });

async function fetchUserSafe(id: string): Promise<User> {
  const res = await fetch(`/api/users/${id}`);
  const data = await res.json();
  return UserSchema.parse(data); // ✨ Throws at runtime if API contract is broken!
}
TypeScript types are completely erased on emit. Without runtime validation (e.g. Zod), type assertions like 'as User' offer zero runtime safety.

Key Subtopics

  • Superset of JavaScript
  • Erase-only type system
  • Compile time vs runtime
  • tsc vs bundlers (Vite, Next, esbuild, swc)
  • Gradual typing

What You Need To Understand

  • Types exist only until emit unless you add runtime validation.
  • Every valid JS program is syntactically valid TS, but not always type-correct under strict settings.
  • TypeScript does not change JavaScript semantics of values at runtime.
  • Next.js/Vite typecheck and transpile differently than raw tsc.

Why It Is Important

  • Prevents the false belief that TypeScript validates API JSON automatically.
  • Frames every later decision about Zod, DTOs, and assertions.

Practical Coding Exercises

  • Create a .ts file that typechecks and inspect the emitted .js; confirm all types disappeared.
  • Write a function that accepts unknown JSON and show that TS will not protect you without narrowing.

Real-World Production Scenarios

  • Explaining to a team why User type on fetch() is a lie without parsing.
  • Choosing whether a package should ship .d.ts only or runtime schemas.

Common Junior Mistakes

  • Assuming TypeScript runs in the browser.
  • Thinking 'as User' makes network data safe.
  • Confusing Next.js build errors with tsc --noEmit project errors.

Target Interview Questions

  • Does TypeScript exist at runtime?
  • If types are erased, why bother using TS?
  • What does 'soundness' mean in TS?
⚡ Quick Assessment Drill
Checkpoint Challenge: Write a function parseUser(raw: unknown): User that throws an Error if raw is not an object or lacks a string 'id', demonstrating that TypeScript types do not exist at runtime.
💡 Reveal Model Solution & Explanation 
type User = { id: string };

function parseUser(raw: unknown): User {
  if (typeof raw === "object" && raw !== null && "id" in raw && typeof (raw as Record<string, unknown>).id === "string") {
    return { id: (raw as Record<string, unknown>).id as string };
  }
  throw new Error("Invalid User data received at runtime");
}
Explanation: Because TypeScript types are completely erased at compile-time, checking the shape of runtime data requires explicit JavaScript typeof and in operator checks.
Priority: Core Difficulty: Beginner Prerequisites: Comfortable JavaScript (functions, objects, arrays, promises, modules). Status: Current / relevant

1.3 Primitive types and special types (first pass)

TypeScript · Primitives, Top Types, and Bottom Types
// Primitives
const id: string = "usr_01";
const count: number = 42;          // NaN, Infinity, floats are all 'number'
const isActive: boolean = true;
const key: symbol = Symbol("id");
const bigVal: bigint = 9007199254740991n;

// Special Types
let ignored: void = undefined;    // Returned by functions that don't return values
let rawJson: unknown = JSON.parse('{"a":1}'); // Safe top type (requires narrowing)

// Exhaustiveness / Unreachable bottom type
function throwError(msg: string): never {
  throw new Error(msg); // Never returns normally
}
'unknown' is the type-safe top type forcing you to verify values before usage; 'never' represents unreachable code or empty sets.

Key Subtopics

  • string, number, boolean
  • null, undefined
  • bigint, symbol
  • void, never, any, unknown (intro)
  • object (the type) vs objects

What You Need To Understand

  • number is all JS numbers including NaN; there is no int type.
  • object means 'not primitive' and is almost never what you want.
  • void means the return value will not be used.
  • never means the value cannot exist / function does not return.
  • any turns the type system off; unknown forces narrowing.

Why It Is Important

  • These are the atoms of every API response, form field, and DB column mapping.

Practical Coding Exercises

  • Annotate a user id, email, isActive, createdAt.
  • Write a function returning void and one returning never (throw).
  • Pass null into a string parameter under strictNullChecks and read the error.

Real-World Production Scenarios

  • Form fields, feature flags, environment variables, DB scalars.

Common Junior Mistakes

  • Using Number / String object wrapper types instead of lowercase primitives.
  • Typing IDs as number when they are UUID strings.
  • Using object for records.

Target Interview Questions

  • Difference between void and undefined?
  • When does a function get type never?
  • null vs undefined in TS?
⚡ Quick Assessment Drill
Checkpoint Challenge: Type a function failProcess(reason: string): never that guarantees it never returns normally.
💡 Reveal Model Solution & Explanation 
function failProcess(reason: string): never {
  throw new Error(`Process failed: ${reason}`);
}
Explanation: The 'never' type indicates a function whose execution cannot reach an end point, either by throwing an exception or looping infinitely.

1.4 Type annotations vs type inference

TypeScript · When to Annotate vs When to Let TS Infer
// ❌ OVER-ANNOTATION (NOISY):
const count: number = 10;
const greeting: string = "Hello World";

// ✅ CLEAN INFERENCE:
const inferredCount = 10;          // TS infers: number
const inferredGreeting = "Hello";  // TS infers: "Hello" (literal const)

// ✅ CRITICAL ANNOTATION BOUNDARIES: Function inputs & Public API returns
export function calculateTax(subtotal: number, rate: number): number {
  return subtotal * rate;
}

// Contextual typing: TS infers 'item' parameter type from array elements:
[1, 2, 3].map((item) => item * 2); // 'item' is automatically inferred as number
Annotate public boundaries, exported function signatures, and complex state; let the compiler infer local variables and contextual callbacks.

Key Subtopics

  • Variable annotations
  • Contextual typing
  • Return type inference
  • When to annotate explicitly
  • Best-practice annotation surfaces

What You Need To Understand

  • TS infers from initialization and from context (e.g. callbacks).
  • Annotate public function inputs and shared API boundaries.
  • Do not annotate every local const x: number = 1 — noise.
  • Missing annotations on exported functions make inference part of your public contract.

Why It Is Important

  • Over-annotation hides inference skill; under-annotation leaks any across files.

Practical Coding Exercises

  • Write 10 locals with no annotations and inspect inferred types in the IDE.
  • Export a function without a return annotation; change the implementation and watch callers break.
  • Add explicit return types on a public service module.

Real-World Production Scenarios

  • Service layer functions, React component props (explicit), internals (inferred).

Common Junior Mistakes

  • Annotating every variable.
  • Leaving exported functions unannotated so return types drift.
  • Using any because inference failed instead of fixing the expression.

Target Interview Questions

  • Should you always write return types?
  • What is contextual typing?
⚡ Quick Assessment Drill
Checkpoint Challenge: Show an example of contextual typing where a callback parameter does not need any explicit type annotation.
💡 Reveal Model Solution & Explanation 
const scores = [85, 92, 78];
// 'score' is contextually inferred as number from scores:
scores.forEach((score) => {
  console.log(score.toFixed(1));
});
Explanation: Contextual typing allows TypeScript to deduce the types of function parameters based on the location in which the function expression appears.
Priority: Core Difficulty: Beginner Prerequisites: 1.3 Status: Current / relevant

1.5 Arrays, tuples, and readonly arrays

TypeScript · Homogeneous Arrays vs Positional Tuples
// 1. Homogeneous Array
const numbers: number[] = [1, 2, 3];
numbers.push(4); // OK

// 2. Fixed-position Tuple: [latitude, longitude, city]
type GeoPoint = readonly [number, number, string];
const office: GeoPoint = [28.6139, 77.2090, "New Delhi"];
// office[0] = 30.0; // ❌ COMPILE ERROR: Cannot assign to read only property

// 3. React hook returning a typed tuple [state, toggleAction]:
import { useState, useCallback } from "react";

export function useToggle(initial: boolean = false): [boolean, (next?: boolean) => void] {
  const [value, setValue] = useState(initial);
  const toggle = useCallback((next?: boolean) => {
    setValue((prev) => (typeof next === "boolean" ? next : !prev));
  }, []);
  return [value, toggle];
}
Tuples encode fixed positions and length; typed [boolean, (next?: boolean) => void] tuple supports both toggle and explicit boolean setting.

Key Subtopics

  • T[] vs Array<T>
  • Tuples [string, number]
  • Optional tuple elements
  • readonly T[]
  • as const arrays

What You Need To Understand

  • Arrays are homogeneous; tuples encode fixed positions.
  • Push/pop on tuples is a common footgun unless marked readonly.
  • readonly prevents mutation in the type system, not at runtime if you cast.

Why It Is Important

  • API lists, table rows, [lat, lng], React state lists, CSV columns.

Practical Coding Exercises

  • Type a Point as a tuple and as an object; compare usability.
  • Make a readonly string array and try .push.
  • Type useState list of todos.

Real-World Production Scenarios

  • Coordinates, RGB, argument lists, Excel-like rows.

Common Junior Mistakes

  • Using arrays where a tuple is needed.
  • Mutating arrays that were meant to be immutable state.

Target Interview Questions

  • Array vs tuple?
  • How do you type a fixed pair of id and name?
⚡ Quick Assessment Drill
Checkpoint Challenge: Define a readonly tuple for a coordinate [latitude: number, longitude: number] and demonstrate that attempting to modify an index fails compilation.
💡 Reveal Model Solution & Explanation

const loc: Coordinate = [28.6139, 77.2090];
// loc[0] = 30; // ❌ COMPILE ERROR: Cannot assign to '0' because it is a read-only property.
Explanation: Marking a tuple with 'readonly' prevents index mutations and method calls like .push() or .pop() in the type system.

1.6 Functions — beginner

TypeScript · Parameter Types, Optionality, and Void Returns
// Optional parameter (?) vs Default parameter
function sendInvite(toEmail: string, role: string = "member", note?: string): boolean {
  console.log(`Inviting ${toEmail} as ${role}${note ? ` with note: ${note}` : ""}`);
  return true;
}

// Function Type Signatures:
type Logger = (message: string, level?: "info" | "warn" | "error") => void;

// Void-returning callback nuance:
// Callbacks returning void allow implementations that return values (return is ignored)
const logToConsole: Logger = (msg) => {
  return console.log(msg); // Allowed even though console.log returns undefined!
};
A function signature returning 'void' allows callers to ignore the return value, which is why Array.prototype.forEach allows return statements.

Key Subtopics

  • Parameter types
  • Return types
  • Optional and default params
  • Rest params
  • Function type expressions
  • void-returning callbacks

What You Need To Understand

  • Optional ? is different from | undefined in call sites (caller can omit ?).
  • A function that returns a value can still be assigned to () => void (return value ignored).
  • Callback types must encode arity and return use.

Why It Is Important

  • Every handler, mapper, predicate, and service method is a function type.

Practical Coding Exercises

  • Type map, filter, and a custom forEach.
  • Write a logger (...args: unknown[]) => void.
  • Type a function with optional config object.

Real-World Production Scenarios

  • Express handlers later, React event handlers, array methods.

Common Junior Mistakes

  • Typing callbacks as Function (loosens all checking).
  • Forgetting return type on recursive functions.
  • Using any[] for rest args.

Target Interview Questions

  • Optional parameter vs T | undefined?
  • Why can a number-returning function be passed where void is expected?
⚡ Quick Assessment Drill
Checkpoint Challenge: Write a function type alias for a comparator function that accepts two numbers and returns a number.
💡 Reveal Model Solution & Explanation 
type Comparator = (a: number, b: number) => number;
const ascending: Comparator = (x, y) => x - y;
Explanation: Function type expressions define the parameter types and return type signature cleanly for reuse across algorithms.
Priority: Core Difficulty: Beginner Prerequisites: 1.4 Status: Current / relevant

1.7 Object types — beginner

TypeScript · Object Shapes, Excess Property Checks & Readonly
type UserProfile = {
  readonly id: string;        // Cannot be reassigned
  name: string;
  email: string;
  avatarUrl?: string;         // Optional property
};

function updateUser(user: UserProfile) {
  // user.id = "new_id"; // ❌ COMPILE ERROR: Cannot assign to 'id' because it is a read-only property
}

// ⚠️ EXCESS PROPERTY CHECKS:
// Fresh object literals are checked strictly:
// updateUser({ id: "1", name: "A", email: "a@b.com", extra: 123 }); // ❌ Error: 'extra' does not exist!

// But if passed via an intermediate variable:
const data = { id: "1", name: "A", email: "a@b.com", extra: 123 };
updateUser(data); // ✅ Compiles! Structural typing allows extra properties on existing variables.
Excess property checks catch typos in fresh object literals; passing values via a variable reverts to standard structural subtyping.

Key Subtopics

  • Object type literals
  • Optional properties
  • readonly properties
  • Excess property checks
  • Index signatures (intro)
  • Nested objects

What You Need To Understand

  • Fresh object literals are checked extra-strict (excess properties).
  • Optional property means the key may be absent.
  • Index signatures allow open-ended keys but weaken type safety.

Why It Is Important

  • Almost all domain models start as object types.

Practical Coding Exercises

  • Model User, Address, Order with nested objects.
  • Pass an extra property in an object literal and explain the error.
  • Add an index signature and show what safety you lost.

Real-World Production Scenarios

  • JSON API bodies, React props, DB row shapes.

Common Junior Mistakes

  • Using empty interface {} thinking it means empty object (use Record<string, never>).
  • Optional vs | undefined confusion.

Target Interview Questions

  • What are excess property checks?
  • Optional property vs property with undefined?

1.8 Type aliases

TypeScript · Naming Types, Unions, and Function Signatures
// 1. Primitive Alias (Note: structural, NOT nominal)
type UserId = string; 
const id: UserId = "usr_99"; // Still assignable to any string!

// 2. Union Alias
type HttpMethod = "GET" | "POST" | "PUT" | "DELETE" | "PATCH";

// 3. Complex Function & Handler Alias
type AsyncHandler<TInput, TOutput> = (input: TInput) => Promise<TOutput>;

// 4. Object Alias
type GeoCoordinate = {
  lat: number;
  lng: number;
};
Type aliases give a readable name to any type construct (unions, primitives, tuples, intersections). They do not create nominal boundaries.

Key Subtopics

  • type Name = ...
  • Aliasing unions, objects, functions
  • Exporting aliases
  • Aliases do not create new identities

What You Need To Understand

  • A type alias is a name, not a new nominal type.
  • Prefer aliases for unions and function types; interfaces also work for objects.

Why It Is Important

  • Reusable domain vocabulary: UserId, Email, ApiResult.

Practical Coding Exercises

  • Create type ID = string then later upgrade toward branded IDs in Level 4.
  • Alias a function type type Mapper<T, U> = (t: T) => U.

Real-World Production Scenarios

  • Shared types package, form models.

Common Junior Mistakes

  • Believing type UserId = string prevents passing a random string (it does not without branding).

Target Interview Questions

  • Does a type alias make a distinct type?
  • Alias vs interface for a union?

1.9 Interfaces — beginner

TypeScript · Extending Interfaces & Declaration Merging
interface Person {
  id: string;
  name: string;
}

// 1. Extending interfaces:
interface Employee extends Person {
  department: string;
  salary: number;
}

// 2. Declaration Merging (Augmentation):
// If two interfaces share the same name in the same scope, they merge!
interface Window {
  customAnalyticsId?: string; // Merged into global Window
}

// Type aliases CANNOT merge:
// type Person = { id: string };
// type Person = { name: string }; // ❌ Duplicate identifier 'Person'
Interfaces are open for extension and declaration merging; type aliases cannot be merged and can model unions and primitives.

Key Subtopics

  • interface syntax
  • Optional/readonly members
  • Extending interfaces
  • Declaration merging (awareness)
  • Interface vs type — first comparison

What You Need To Understand

  • Interfaces are extendable and merge across declarations.
  • Types are better for unions, tuples, mapped types.
  • For object shapes, both work; teams pick a convention.

Why It Is Important

  • Public object contracts, library typings, React props in many codebases.

Practical Coding Exercises

  • interface User, interface Admin extends User.
  • Show two interface User blocks merging unexpectedly.

Real-World Production Scenarios

  • Component props, repository interfaces.

Common Junior Mistakes

  • Merging by accident when files repeat the same interface name.
  • Using interface for a union.

Target Interview Questions

1.10 Union types — beginner

TypeScript · Handling Disjoint Types & Narrowing
type ApiResponse = 
  | { success: true; data: string[] }
  | { success: false; errorMessage: string };

function handleResponse(res: ApiResponse) {
  // res.data; // ❌ COMPILE ERROR: Property 'data' does not exist on type '{ success: false... }'
  
  if (res.success) {
    console.log("Users:", res.data); // ✅ Auto-narrowed!
  } else {
    console.error("Failed:", res.errorMessage); // ✅ Auto-narrowed!

}

What You Need To Understand

  • A union is one of several types, not a mix of all fields at once.
  • You must narrow before using constituent-specific fields.

Why It Is Important

  • The most important modeling tool after basic objects. Server responses, UI state, role flags.

Practical Coding Exercises

1.11 any, unknown, never, void — working knowledge

TypeScript · The Quartet: any vs unknown vs never vs void
// 1. any: Disables type-checker completely (viral contagion!)
let bad: any = 10;
bad.nonExistentMethod(); // Compiles! Crashes at runtime!

// 2. unknown: Safe top type. Forces narrowing before usage.
let safe: unknown = JSON.parse('{"status": "ok"}');
// safe.status; // ❌ COMPILE ERROR: Object is of type 'unknown'
if (typeof safe === "object" && safe !== null && "status" in safe) {
  console.log((safe as Record<string, unknown>).status); // Safe after checking!
}

// 3. void: Function produces no usable value
function logEvent(name: string): void {
  console.log("Event:", name);
}

// 4. never: Value cannot exist. Used for exhaustive checks.
function assertNever(x: never): never {
  throw new Error(`Unexpected value reached: ${JSON.stringify(x)}`);
}
Use 'unknown' at all untrusted boundaries (JSON parsing, catch clauses); use 'never' to guarantee compile-time exhaustiveness in switches.

Key Subtopics

  • any disables checking
  • unknown is the safe top type
  • never is the bottom type
  • void for ignored returns
  • Trust boundaries

What You Need To Understand

  • At JSON.parse, env vars, and network edges, start with unknown.
  • never is used in exhaustive switches.
  • any is contagious through inference.

Why It Is Important

  • This quartet is in almost every mid-level and senior interview.

Practical Coding Exercises

  • Wrap JSON.parse as parseUnknown(text: string): unknown.
  • Write assertNever(x: never): never.
  • Trace how one any infects a file.

Real-World Production Scenarios

  • API parsing, default exports from untyped libs, error catch clauses (unknown).

Common Junior Mistakes

  • catch (e: any).
  • Annotating state as any 'temporarily' forever.
  • Using never and void interchangeably.

Target Interview Questions

  • Why is unknown better than any?
  • What is the bottom type in TypeScript?
⚡ Quick Assessment Drill
Checkpoint Challenge: Explain and demonstrate why unknown is safer than any when handling untrusted data.
💡 Reveal Model Solution & Explanation 
let unsafeData: any = "hello";
unsafeData.nonExistent(); // Compiles! Crashes at runtime!

let safeData: unknown = "hello";
// safeData.nonExistent(); // ❌ Compile Error! Must narrow first:
if (typeof safeData === "string") {

// 2. CONTRAVARIANCE (Parameter Types under strictFunctionTypes):
// A function that handles ANY Animal CAN be passed where a function expecting Dog is needed:

// The opposite is UNSOUND:
let unsafeConsumeDog: (d: Dog) => void = (d) => d.bark();
// let unsafeAssign: (a: Animal) => void = unsafeConsumeDog; 
// ❌ COMPILE ERROR: Cannot pass a general Animal to a function that calls d.bark()!

Q1 Does TypeScript exist at runtime?
▼

No. Types are completely erased during compilation. Only emitted JavaScript plus any runtime validators you add (Zod, etc.) remain. That is why type assertions like 'as User' do not check network JSON.

Category: Foundations Production Verified
Q2 If types are erased, why use TypeScript?
▼

It catches entire classes of bugs before deploy, documents contracts, enables confident refactoring and IDE navigation, and makes illegal states harder to represent. It does not replace tests or runtime validation.

Category: Foundations Production Verified
Q3 What does strict mode turn on?
▼

A bundle of safety flags, notably strictNullChecks, strictFunctionTypes, strictBindCallApply, noImplicitAny, noImplicitThis, alwaysStrict, and useUnknownInCatchVariables on modern versions. Teams should always start with strict: true.

Category: Foundations Production Verified
Q4 any vs unknown vs never vs void?
▼

'any' disables checking and infects inference virally. 'unknown' is a safe top type that must be narrowed before usage. 'never' is the bottom type — no value, used for exhaustiveness and functions that throw. 'void' means the return value is not to be used.

Category: Foundations Production Verified
Q5 null vs undefined in TypeScript?
▼

Both are distinct under strictNullChecks. Optional properties mean the key may be absent. exactOptionalPropertyTypes further distinguishes missing keys from explicitly passed undefined. APIs and DB layers should be explicit about which they use.

Category: Foundations Production Verified
Q6 What is type inference?
▼

The compiler figures out types from initializers and context so you need fewer annotations. You still annotate public boundaries. Inference is not mind-reading — useState(null) needs a type argument.

Category: Foundations Production Verified
Q7 When should you write explicit return types?
▼

On exported functions, recursive functions, and public API surfaces. Internals can often infer. Explicit returns lock the contract so implementations cannot silently change what callers receive.

Category: Foundations Production Verified
Q8 Interface vs type alias?
▼

Both describe object shapes. Interfaces can extend and merge declarations; type aliases can express unions, tuples, mapped types, and primitives. For objects, pick a team convention. For unions, you must use type.

Category: Foundations Production Verified
Q9 What is declaration merging?
▼

Multiple interface (or namespace) declarations with the same name combine automatically. Useful for augmenting libraries (like Express Request). Type aliases do not merge. Accidental merging is a bug.

Category: Foundations Production Verified
Q10 What is structural typing?
▼

Compatibility is by shape, not by name. If a value has the required fields, it is assignable. This is duck typing at compile time. Nominal-like behavior needs branding.

Category: Foundations Production Verified
Q11 What are excess property checks?
▼

When you pass a fresh object literal, TS flags extra properties as likely typos. If the same object is first assigned to a variable, those extra properties are allowed under structural typing. This surprise is interview-famous.

Category: Foundations Production Verified
Q12 Union vs intersection?
▼

A | B is one or the other. A & B must satisfy both. Object unions need narrowing; object intersections combine fields. Conflicting primitives in an intersection collapse toward never.

Category: Foundations Production Verified
Q13 What is a literal type?
▼

A type that is a specific value, like 'admin' or 42. Unions of literals model finite sets. Widening turns 'admin' into string when inferred from let.

Category: Foundations Production Verified
Q14 What is widening?
▼

Mutable inference often generalizes literals to string/number/boolean. 'as const' and const bindings preserve literals. This is why config objects need 'as const' or 'satisfies'.

Category: Foundations Production Verified
Q15 Explain discriminated unions.
▼

A union of objects sharing a literal tag field. Switching on the tag narrows the rest of the fields. Ideal for async UI state and API results. Makes impossible combinations unrepresentable.

Category: Unions Production Verified
Q16 How do you make a switch exhaustive?
▼

Handle every variant, then in default assign the value to never or call assertNever(x: never). Adding a new variant becomes an immediate compile error.

Category: Unions Production Verified
Q17 What is a type predicate?
▼

A function return type 'x is User' that, if the function returns true, narrows x in the caller. If you implement it incorrectly, TS still trusts the signature — predicates can lie.

Category: Unions Production Verified
Q18 typeof vs instanceof vs in?
▼

'typeof' works for primitives. 'instanceof' works for classes/constructors. 'in' checks for a property name on an object and narrows unions that do or do not have that key.

Category: Unions Production Verified
Q19 What does 'as' do?
▼

A compile-time assertion. No runtime conversion. Use after you have actually proven the type, or after parsing. 'as any' and double assertions via unknown are escape hatches, not design.

Category: Unions Production Verified
Q20 as const vs satisfies?
▼

'as const' freezes literal types and makes properties readonly. 'satisfies T' checks that a value matches T while keeping the precise inferred type. Often used together on config.

Category: Unions Production Verified
Q21 Why do teams avoid enums?
▼

Numeric enums have reverse mapping and surprising assignability. Enums are runtime objects. IsolatedModules/const enums can break. Literal unions plus const objects are usually simpler and tree-shake cleanly. Still know enums for legacy code.

Category: Unions Production Verified
Q22 What are generics for?
▼

Parameterizing types so one implementation works for many types without using any. Example: function first<T>(xs: T[]): T | undefined. Constraints (T extends ...) restore operations you need.

Category: Generics Production Verified
Q23 What is a generic constraint?
▼

T extends U limits T so you can use U’s properties. Example: T extends { id: string }. Without constraints you cannot read t.id.

Category: Generics Production Verified
Q24 Pick vs Omit vs Partial vs Required?
▼

Pick keeps listed keys. Omit removes listed keys. Partial makes all keys optional (shallow). Required makes all keys required (shallow). Nested objects are not deep-transformed.

Category: Generics Production Verified
Q25 How do you type a dictionary?
▼

Record<Key, Value>, often Record<string, User> or Record<Role, Permission[]>. Prefer finite key unions over string when the key set is known.

Category: Generics Production Verified
Q26 keyof T?
▼

A union of T’s property names. keyof {a:1,b:2} is 'a'|'b'. On a union of objects, keyof gives keys common to all members.

Category: Generics Production Verified
Q27 typeof in type position?
▼

Queries the type of a value: type Cfg = typeof config. Combined with 'as const' you derive literal unions from runtime objects.

Category: Generics Production Verified
Q28 Indexed access T[K]?
▼

The type of property K on T (e.g. User['id']). If K is a key union, you get a union of property types. T[number] is the element type of an array/tuple.

Category: Generics Production Verified
Q29 What is a mapped type?
▼

A type that iterates keys: { [K in keyof T]: T[K] | null }. Can add/remove ? and readonly, and remap keys with 'as'.

Category: Generics Production Verified
Q30 What is a conditional type?
▼

T extends U ? X : Y. Type-level if. Distributes over naked unions, which is how Exclude filters unions.

Category: Generics Production Verified
Q31 What does distributive mean?
▼

For a naked type parameter, T extends Foo ? X : Y applied to A|B becomes (A extends Foo ? X : Y) | (B extends Foo ? X : Y). Wrap as [T] extends [Foo] to avoid that.

Category: Generics Production Verified
Q32 What is infer?
▼

Inside a conditional extends, infer R captures a matched piece: T extends (...args: any) => infer R ? R : never is ReturnType.

Category: Generics Production Verified
Q33 Template literal types?
▼

String types composed with `${A}${B}`. Unions distribute, so they can model routes and event names. They can also explode compile time.

Category: Generics Production Verified
Q34 What is never used for in practice?
▼

Exhaustive checks, filter-out branches in conditionals (Exclude), functions that throw or infinite-loop, and intersections that cannot exist.

Category: Unions Production Verified
Q35 Why is object a bad annotation?
▼

It means any non-primitive. You cannot safely read fields. Prefer a specific shape, Record<string, unknown>, or unknown.

Category: Foundations Production Verified
Q36 Function assignability and void?
▼

A function returning a value may be assigned where void is expected because the return will be ignored. This is why array.forEach(fn) allows mappers that return values.

Category: Classes Production Verified
Q37 Optional param vs T | undefined?
▼

Optional means the argument can be omitted. A required (x: T | undefined) still requires the caller to pass something (possibly undefined). Under some flags, optional properties also differ from | undefined.

Category: Unions Production Verified
Q38 private vs #private?
▼

TS private is only a compile-time visibility check; casts and emit still expose the field. #private is JavaScript runtime privacy. Use # when you need actual encapsulation.

Category: Classes Production Verified
Q39 implements vs extends?
▼

extends inherits implementation. implements checks that the instance matches a shape. It does not generate methods. Static side is not fully checked by implements.

Category: Classes Production Verified
Q40 Are TypeScript classes nominally typed?
▼

Mostly structurally. Two classes with the same public shape assign. private fields make classes behave more nominally because the private member is unique.

Category: Classes Production Verified
Q41 What is variance?
▼

How subtyping composes through containers and functions. Returns are covariant: () => Dog is a () => Animal. Parameters are contravariant under strictFunctionTypes.

Category: Classes Production Verified
Q42 What does strictFunctionTypes change?
▼

It makes function parameters checked contravariantly for function types. Safer callback typing, more errors on unsound assignments.

Category: Classes Production Verified
Q43 Why can extra properties pass when assigned via a variable?
▼

Excess property checks apply to fresh literals. After assignment, only structural assignability remains, so extra fields are allowed if required fields match.

Category: Foundations Production Verified
Q44 What is freshness?
▼

The extra-strict checking of object literals to catch typos before they are widened into general structural shapes.

Category: Foundations Production Verified
Q45 How do you get nominal IDs?
▼

Branded types: string & { readonly __brand: unique symbol } plus a parser. Still erased at runtime, so parse at boundaries.

Category: Advanced Production Verified
Q46 What is a .d.ts file?
▼

A declaration file containing only types. Describes JS to the checker. Published by libraries or written for untyped modules.

Category: Advanced Production Verified
Q47 What is an ambient declaration?
▼

declare const API_KEY: string or declare module 'foo'. Introduces a type for something that exists at runtime without implementing it in this file.

Category: Advanced Production Verified
Q48 How do you type an untyped package?
▼

Add a foo.d.ts with declare module 'foo' { export function bar(): void } or install @types/foo. Keep the declarations honest.

Category: Advanced Production Verified
Q49 What is module augmentation?
▼

declare module 'express' { interface Request { user?: AuthUser } }. Adds to an existing module’s types. The file must be included in compilation.

Category: Advanced Production Verified
Q50 import type vs import?
▼

import type is erased and cannot be used as a value. Helps isolatedModules and prevents accidental runtime imports of type-only modules.

Category: Advanced Production Verified
Q51 What is isolatedModules?
▼

Each file must be transpilable without the whole program. Required by Babel, SWC, Vite, and Next.js compilers.

Category: Advanced Production Verified
Q52 moduleResolution bundler vs node16/nodenext?

Category: Advanced Production Verified
Q53 What is esModuleInterop?
▼

Category: Advanced Production Verified
Q54 Why noEmit in Next apps?

Category: Advanced Production Verified
Q55 What does skipLibCheck do?

Category: Advanced Production Verified
Q56 noUncheckedIndexedAccess?

Category: Advanced Production Verified
Q57 exactOptionalPropertyTypes?

▼

Cursor: { items: T[]; nextCursor: string | null }. Offset: { items: T[]; page: number; pageSize: number; total: number }. Do not mix fields that cannot coexist without a union.

Category: Unions Production Verified
Q91 How would you type feature flags?
▼

const flags = { newCheckout: true } as const then type Flag = keyof typeof flags. Or a schema if flags load remotely.

Category: React Production Verified
Q92 How do you type RBAC?
▼

type Role = 'admin' | 'editor' | 'viewer' and functions can(role, action). Avoid boolean soup. UI and server share the role union; server still enforces.

Category: React Production Verified
Q93 What would you look for in a TS code review?
▼

any, unjustified as, optional fields that should be a union, DTOs leaking rows, unvalidated req.body, missing exhaustive switches, React.FC cargo cult, env access without checks.

Category: Production Production Verified
Q94 How do you migrate a JS codebase?
▼

allowJs + checkJs or rename file by file. Strictest first on new files. Wrap untyped boundaries. Do not rewrite everything at once. skipLibCheck stays on.

Category: Foundations Production Verified
Q95 What is the difference between compile errors and runtime validation errors?
▼

Compile errors are about your program’s types. Validation errors are about data from the world. Users never see tsc errors; they see 400s from Zod.

Category: Foundations Production Verified
Q96 Explain ReturnType and Parameters.
▼

ReturnType<typeof fn> extracts the return type. Parameters<typeof fn> is a tuple of argument types. Both fail on overloaded functions in surprising ways.

Category: Generics Production Verified
Q97 Why might Omit misbehave on a union?
▼

Omit is usually implemented as a mapped type over the union as a whole, which can collapse discriminants. You may need a distributive Omit.

Category: Generics Production Verified
Q98 How do you type a function that returns different types based on input?
▼

Prefer overloads or generic literals: function get<T extends Key>(k: T): Map[T]. Conditionals can describe it. Avoid any returns.

Category: Generics Production Verified
Q99 What is contextual typing?
▼

The expected type of a location flows inward, e.g. array method callbacks infer parameter types from the array. Annotations on the outer value help inner inference.

Category: Foundations Production Verified
Q100 How do path aliases affect runtime?
▼

TS paths are compile-time. Node/bundler must implement the same mapping. Next/Vite do; raw node dist/index.js will not unless you emit relative paths or use a runtime resolver.

Category: Advanced Production Verified
Q101 What is a project reference?
▼

A tsconfig references another project so tsc -b builds a graph. Useful in monorepos. Requires composite and declaration emit on the referenced project.

Category: Advanced Production Verified
Q102 How do you type CSS modules or image imports?
▼

Ambient declare module '*.module.css' { const classes: Record<string, string>; export default classes } and similar for images. Next often ships these.

Category: Advanced Production Verified
Q103 Decorators in interviews?
▼

Say they are used by Nest/Angular, come in legacy and new flavors, and are unnecessary for Express/React. Do not pretend you use them if you do not.

Category: Production Production Verified
Q104 How would you design types for a checkout flow?
▼

Discriminated steps: cart -> shipping -> payment -> confirmed. Each step carries only the data it has. Payment result is success|failure. Inventory errors are a variant, not a boolean.

Category: Unions Production Verified
Q105 How would you type a webhook handler?
▼

Verify signature first (runtime). Parse body with z.discriminatedUnion('type', ...). Exhaustive handle. Unknown type -> never / log / 400.

Category: Unions Production Verified
Q106 What is the type of this in a standalone function?
▼

Under noImplicitThis / strict, unbound this is an error unless typed. In methods, this is the instance. Arrow functions capture lexical this and do not have their own this type.

Category: Classes Production Verified
Q107 How do you type higher-order functions?
▼

Generics on input and output function types: function memoize<A extends unknown[], R>(fn: (...a: A) => R): (...a: A) => R. Constraints keep call sites inferable.

Category: Generics Production Verified
Q108 What breaks generic inference?
▼

Too few type params, early unknown annotations, boxing values as any, overloads that are too wide, and not placing T where it can be inferred from an argument.

Category: Generics Production Verified
Q109 How do you type rest and spread?
▼

Rest args as tuples when order matters: ...args: [string, number]. Spread in objects uses intersection-like results; excess fields follow object assignability rules.

Category: Production Production Verified
Q110 What is this parameter syntax?
▼

function f(this: HTMLElement, ev: Event) types this without being a runtime argument. Callers must invoke it as a method of that type.

Category: Classes Production Verified
Q111 Is TypeScript object-oriented or functional?
▼

It is a type system on JavaScript, so both styles work. Interviews want you to model data with unions more than to build deep class hierarchies.

Category: Classes Production Verified
Q112 How do you handle versioning of types?
▼

Version HTTP contracts (/v2) rather than mutating PublicUser in breaking ways. Shared packages use semver. Additive optional fields are safer than changing meanings.

Category: Production Production Verified
Q113 What is the worst TypeScript code you have seen — what was wrong?
▼

Prepare a real story: any everywhere, one User type for DB+API, assertions on fetch, boolean state soup. Explain how unions + Zod + DTOs fixed it.

Category: Production Production Verified
Q114 How do you learn a new library’s types?
▼

Hover in the IDE, jump to .d.ts, look for generics on the main function, search for overloads. Do not fight the library with as any first.

Category: Production Production Verified
Q115 What would you enable after strict?
▼

noUncheckedIndexedAccess, noImplicitOverride, noFallthroughCasesInSwitch, exactOptionalPropertyTypes (carefully), type-aware ESLint no-unsafe-*.

Category: Advanced Production Verified
Q116 How do you test types?
▼

expect-type or tsd, plus @ts-expect-error for cases that must fail. App teams rarely need this except in shared utility packages.

Category: Production Production Verified
Q117 Explain a time types forced a better design.
▼

Prepare this. Example: replacing isLoading+error+data with AsyncState deleted a UI bug where spinner and error showed together.

Category: Unions Production Verified
Q118 What is JSX namespace typing?
▼

TS uses JSX.IntrinsicElements to know valid tags and their props. @types/react fills this. Custom elements can be added via interface merging.

Category: Advanced Production Verified
Q119 How are default generics used?
▼

type ApiResponse<T = unknown> = { data: T }. Defaults help when T cannot be inferred. Do not default to any.

Category: Generics Production Verified
Q120 What is a recursive JSON type?
▼

type Json = string | number | boolean | null | Json[] | { [k: string]: Json }. Shows you understand recursive aliases.

Category: Generics Production Verified
Q121 Why might tsc be slow?
▼

Huge unions from template literals, deep instantiations, no project split, checking all node_modules without skipLibCheck, pathologically complex mapped types.

Category: Advanced Production Verified
Q122 How do you type environment-specific Next config?
▼

Separate server env schema from public NEXT_PUBLIC_* schema. Never infer server secrets on the client.

Category: Boundaries Production Verified
Q123 What is the type-safe way to do dynamic object access?
▼

Constrain the key: function get<T, K extends keyof T>(o: T, k: K): T[K]. Avoid o[key as string].

Category: Generics Production Verified
Q124 How do you type errors in fetch wrappers?
▼

Do not pretend fetch returns User. unknown -> schema parse -> Result<User, NetworkError | ValidationError>.

Category: Boundaries Production Verified
Q125 What should a 3-year TS engineer know that a 6-month engineer may not?
▼

Boundary validation, DTO mapping, discriminated state, module augmentation, tsconfig that matches runtime, reading .d.ts, when not to write clever types.
