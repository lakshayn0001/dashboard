Audio briefing for 4.1 Type inference internals (practical model). Core concept: Type inference flows bi-directionally; contextual typing pushes expected types into lambda arguments, preventing unnecessary annotations. Key principles: The checker infers the most general type that still fits, with special cases for literals and contextual typing. You do not need the compiler source; you need a working mental model. Why this matters in production: Debugging 'why did this become unknown?' in generic components and helpers. Common pitfall to avoid: Adding any when an extra type parameter would have saved inference. Practical takeaway: Passing null without a type argument causes TypeScript to infer the type argument as null, rejecting subsequent User assignments.
