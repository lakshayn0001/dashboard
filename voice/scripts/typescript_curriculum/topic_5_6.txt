Audio briefing for 5.6 Forms, server actions, and field errors. Core concept: Derive form types and server actions from a single Zod schema; map validation failures directly into typed field-error dictionaries. Key principles: Form values should come from a schema, not a hand-copied interface. Error maps should be Partial<Record<keyof FormValues, string>> or schema-shaped. Why this matters in production: Zero discrepancy between client input validation and server database persistence. Common pitfall to avoid: Parallel FormValues type that drifts from the schema. Practical takeaway: z.infer creates an exact TypeScript type that mirrors the runtime validation schema.
