Audio briefing for 7.1 API contracts and DTO strategy. Core concept: Never return raw database rows to the client. Define separate Public DTOs and use Omit or mapping functions to strip secrets. Key principles: DB rows have fields you must not ship (password hash, internal flags). CreateUserDto, PublicUser, UserRow are different types. Why this matters in production: Preventing security data leaks, API versioning stability. Common pitfall to avoid: One User type used for DB, API, and UI. Exporting passwordHash because the type allowed it. Practical takeaway: Separating DTOs from database models prevents client requests from setting system-managed fields.
