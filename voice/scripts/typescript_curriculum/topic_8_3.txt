Audio briefing for 8.3 ESLint and typescript-eslint. Core concept: Type-checked ESLint rules catch unhandled floating promises and unsafe any usage that the raw TypeScript compiler allows. Key principles: Type-aware lint rules catch any infection that humans miss. Type-checked linting needs a tsconfig; it is slower and worth it on apps. Why this matters in production: Catching bugs before code review and automated code cleanliness. Common pitfall to avoid: Disabling the whole rule set to silence one file. Linting without type-aware rules on an unsafe codebase. Practical takeaway: Enforcing type-only imports ensures types are cleanly erased and avoids accidental side-effect module loading.
