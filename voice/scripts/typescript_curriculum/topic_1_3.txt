Audio briefing for 1.3 Primitive types and special types (first pass). Core concept: 'unknown' is the type-safe top type forcing you to verify values before usage; 'never' represents unreachable code or empty sets. Key principles: number is all JS numbers including NaN; there is no int type. object means 'not primitive' and is almost never what you want. Why this matters in production: These are the atoms of every API response, form field, and DB column mapping. Common pitfall to avoid: Using Number / String object wrapper types instead of lowercase primitives. Typing IDs as number when they are UUID strings. Practical takeaway: The 'never' type indicates a function whose execution cannot reach an end point, either by throwing an exception or looping infinitely.
