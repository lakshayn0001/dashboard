Audio briefing for 1.8 Type aliases. Core concept: Type aliases give a readable name to any type construct (unions, primitives, tuples, intersections). They do not create nominal boundaries. Key principles: A type alias is a name, not a new nominal type. Prefer aliases for unions and function types; interfaces also work for objects. Why this matters in production: Reusable domain vocabulary: UserId, Email, ApiResult. Common pitfall to avoid: Believing type UserId = string prevents passing a random string (it does not without branding). Practical takeaway: Type aliases give readable names to complex union types.
