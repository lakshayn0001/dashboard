Audio briefing for 3.13 Module resolution and ESM/CJS interop. Core concept: Under 'NodeNext' module resolution, TypeScript strictly enforces Node's ESM rules, including explicit .js file extensions on relative imports. Key principles: Wrong module + moduleResolution is the #1 Next/Node TS config pain. NodeNext is stricter about file extensions and CJS/ESM boundaries. Why this matters in production: Shipping a package, writing Next + Express monorepos, debugging 'cannot find module'. Common pitfall to avoid: Using bundler resolution for a Node library that runs in plain Node. Ignoring package.json exports. Practical takeaway: Node.js ESM resolution strictly requires file extensions at runtime; TypeScript reflects runtime resolution in its checker.
