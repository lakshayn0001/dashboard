Audio briefing for 2.9 as const and satisfies. Core concept: 'satisfies' checks assignability against a contract while preserving exact literal inference; 'as const' freezes arrays into readonly literal tuples. Key principles: as const preserves literal types and makes properties readonly. satisfies T validates assignability while keeping the more specific inferred type. Why this matters in production: Route tables, feature flags, design tokens, env schemas, const menus. Common pitfall to avoid: Using as T when satisfies T was enough. Forgetting as const and getting string instead of literals. Practical takeaway: satisfies checks that an object satisfies a contract while preserving literal inference for property lookups.
