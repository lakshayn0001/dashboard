Audio briefing for 2.5 Functions — intermediate. Core concept: Overload signatures describe discrete call patterns while the implementation signature handles the union; 'this' can be typed as a pseudo first argument. Key principles: Overloads describe multiple call shapes; implementation signature is wider. Prefer unions or generics over overload piles when possible. Why this matters in production: Library APIs, addEventListener-style functions, fluent builders. Common pitfall to avoid: Implementation signature not compatible with overloads. Too many overloads when one generic would do. Practical takeaway: Overload signatures describe discrete call patterns while a single implementation handles the underlying union.
