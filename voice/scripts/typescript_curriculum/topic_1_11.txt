Audio briefing for 1.11 any, unknown, never, void — working knowledge. Core concept: Use 'unknown' at all untrusted boundaries (JSON parsing, catch clauses); use 'never' to guarantee compile-time exhaustiveness in switches. Key principles: At JSON.parse, env vars, and network edges, start with unknown. never is used in exhaustive switches. Why this matters in production: This quartet is in almost every mid-level and senior interview. Common pitfall to avoid: catch (e: any). Annotating state as any 'temporarily' forever. Practical takeaway: any disables the type checker completely. unknown forces you to perform runtime narrowing before accessing methods or properties.
