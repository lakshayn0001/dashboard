Audio briefing for 1.1 What TypeScript is and is not. Core concept: TypeScript types are completely erased on emit. Without runtime validation (e.g. Zod), type assertions like 'as User' offer zero runtime safety. Key principles: Types exist only until emit unless you add runtime validation. Every valid JS program is syntactically valid TS, but not always type-correct under strict settings. Why this matters in production: Prevents the false belief that TypeScript validates API JSON automatically. Frames every later decision about Zod, DTOs, and assertions. Common pitfall to avoid: Assuming TypeScript runs in the browser. Thinking 'as User' makes network data safe. Practical takeaway: Because TypeScript types are completely erased at compile-time, checking the shape of runtime data requires explicit JavaScript typeof and in operator checks.
