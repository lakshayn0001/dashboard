Audio briefing for 6.2 tsconfig for Node services. Core concept: A server tsconfig differs from a frontend config; it needs sourceMap for production debugging and target set to your Node runtime version. Key principles: A server is not a browser; do not copy the Next tsconfig blindly into a package that runs on Node. Decide: emit with tsc, or run with tsx and typecheck separately. Why this matters in production: API servers, workers, CLIs. Common pitfall to avoid: Emitting into source directory. Forgetting source maps for production stack traces. Practical takeaway: Source maps map production runtime stack traces back to the original TypeScript line numbers.
