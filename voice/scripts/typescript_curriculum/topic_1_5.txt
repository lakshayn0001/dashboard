Audio briefing for 1.5 Arrays, tuples, and readonly arrays. Core concept: Tuples encode fixed positions and length; typed [boolean, (next?: boolean) => void] tuple supports both toggle and explicit boolean setting. Key principles: Arrays are homogeneous; tuples encode fixed positions. Push/pop on tuples is a common footgun unless marked readonly. Why this matters in production: API lists, table rows, [lat, lng], React state lists, CSV columns. Common pitfall to avoid: Using arrays where a tuple is needed. Mutating arrays that were meant to be immutable state. Practical takeaway: Marking a tuple with 'readonly' prevents index mutations and method calls like .push() or .pop() in the type system.
