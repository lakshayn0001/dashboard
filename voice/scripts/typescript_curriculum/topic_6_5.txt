Audio briefing for 6.5 Error modeling. Core concept: Standardize errors either via a custom AppError class with status codes or a functional Result<T, E> discriminated union. Key principles: Pick a strategy: throw AppError, or return Result. Do not mix randomly. Map domain errors to HTTP in one centralized adapter. Why this matters in production: APIs, payment integrations, idempotent jobs. Common pitfall to avoid: Throwing strings. Leaking stack traces to clients. Practical takeaway: Result types model fallible operations as values rather than throwing unchecked exceptions.
