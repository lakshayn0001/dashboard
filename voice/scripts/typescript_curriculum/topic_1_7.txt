Audio briefing for 1.7 Object types — beginner. Core concept: Excess property checks catch typos in fresh object literals; passing values via a variable reverts to standard structural subtyping. Key principles: Fresh object literals are checked extra-strict (excess properties). Optional property means the key may be absent. Why this matters in production: Almost all domain models start as object types. Common pitfall to avoid: Using empty interface {} thinking it means empty object (use Record<string, never>). Optional vs | undefined confusion. Practical takeaway: Fresh object literals are subjected to excess property checks to catch potential typos.
